# OmniBrain (全知记忆总线) - 项目实施蓝图 V2 (重构版)

## 🎯 核心定位重塑 (Embracing the Standard)
在 2026 年 `AGENTS.md` 成为行业标准的大背景下，“项目级规则同步”已被 Git 原生解决。
OmniBrain 的核心价值全面转轨为：**“个人全局记忆层 (L0)”** 与 **“本地经验库 (L2)”** 的跨工具统一分发。
我们不再试图接管具体的项目，而是接管开发者的**数字大脑**。

---

## 🏗️ 架构颠覆：从“软链接中心”到“中心源+推送 (Hub & Spoke)”
之前的“软链接 (Symlink)”和“JSON 注入”方案被彻底废弃。经真机查证，它们是过度设计的根源。
我们采用最朴素、最稳定的架构：**中心化存储 + 普通文件覆盖推送**。

1. **SSOT (唯一真实数据源)**：所有用户数据（全局铁律 L0、经验库 L2）只存在于 `~/.ai-profile/`。
2. **适配器推送 (Push Adapters)**：点击【同步】时，Rust 底层读取 SSOT，根据不同工具的规范，以**普通文件读写**的方式推送到目标目录。
   - **Cursor**：直接推送到 `~/.cursor/rules/omnibrain-global.mdc` (Cursor 原生支持扫描此目录下的 md/mdc 文件)。
   - **Claude Code**：直接覆盖/追加到 `~/.claude/CLAUDE.md`，或利用 `@AGENTS.md` 特性。

**此架构的降维打击效果**：
- ❌ 跨盘软链接断裂？不存在了，因为全是实体文件拷贝。
- ❌ Windows UAC 提权提示？不存在了，普通文件写入不需要管理员权限。
- ❌ 云盘同步死循环？不存在了，没有软链接，云盘正常工作。
- ❌ JSON 解析碎裂与并发防抖？不存在了，Cursor 根本不需要写 JSON。

## 🔪 极致精简：V1 MVP 版本定义
V1 版本只专注打通数据流，回归两周内可落地的现实工程量。

**功能范围 (Scope)**
1. **纯白板 UI (Vue3 + Tailwind)**：左侧双列表（全局规则、经验库），右侧纯文本编辑。不带 Markdown 渲染，不带 AI 润色。
2. **核心推送引擎 (Rust)**：实现基类 Adapter。实现 Cursor 和 Claude 两个具体 Adapter。硬编码默认路径。
3. **安全覆盖逻辑 (幂等与防丢失)**：在推送到目标路径前，检测原有文件。如果是 OmniBrain 生成的文件则直接覆盖；如果是用户原有手写文件，进行标记并追加，防止数据火葬场。
4. **一键同步按钮**：点击后执行批量推送。

## 🛡️ V1 必须处理的工程底线 (P0/P1)

| 问题域 | 解决方案 |
| :--- | :--- |
| **安装包信任危机** | 必须购买 OV 级代码签名证书，或在发布页醒目提供免安装便携版 (Portable)，避免 SmartScreen 拦截。 |
| **幂等性导致的数据重复** | 推送时使用特殊注释标记（如 `<!-- OmniBrain:Start -->`）。每次推送先正则清除旧的 OmniBrain 块，再注入新块。 |
| **优雅卸载 (去无痕)** | 软件内必须提供【清除所有注入】按钮。遍历所有 Adapter，执行删除/剥离逻辑，还原 IDE 纯净状态。 |
| **L2 经验库的按需加载** | V1 承认其为 Best-Effort（尽力而为）。L0 仅作为索引，L2 切割为多个小文件，依赖大模型自身的检索意愿。 |
