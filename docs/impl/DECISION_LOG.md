# CrossBrain — 设计决策记录（DECISION LOG）

> **AI 工具必读声明**：  
> 本文件记录了所有「为什么这样做而不是那样做」的决策。  
> 在你认为某个设计「不合理」、「可以优化」之前，**必须先查阅本文件**。  
> 如果你在未查阅本文件的情况下推翻了某项决策，你的代码将被视为错误实现，需要重做。

## ADR-01：为什么 Antigravity 用独立文件而 Claude Code 用标记块

**决策**：
- Antigravity IDE：L0 规则写入独立文件 `crossbrain-L0.md`，直接覆盖
- Claude Code：L0 规则注入 `CLAUDE.md` 的标记块，不覆盖整个文件

**原因**：
- Antigravity IDE 的 `~/.gemini/config/rules/` 目录支持多个 `.md` 文件共存，每个文件相互独立，可以安全覆盖 CrossBrain 自己的文件而不影响其他文件（如用户已有的 `user_global.md`）
- Claude Code 的全局规则文件 `CLAUDE.md` 是单一文件，用户可能已有自己的规则在里面。直接覆盖会**永久丢失用户数据**，因此必须用标记块注入

**不可推翻**：这是保护用户数据的核心设计，任何形式的简化（如"统一都用覆盖"）都会导致用户数据丢失。

## ADR-02：为什么用 SHA256 前 6 位而不是用文件名

**决策**：slug-hash = `crossbrain-{文件名前缀}-{SHA256内容前6位}`

**原因**：
- 纯文件名方案的问题：用户改了文件名但内容不变，旧目录会变成孤儿 → 被清理 → AI 工具中的技能消失
- 纯内容 hash 方案的问题：文件名信息丢失，调试困难
- 组合方案：文件名提供可读性，内容 hash 提供精准追踪

**不可推翻**：如果你把 slug-hash 改为只用文件名，文件重命名后孤儿清理会误删仍有效的技能目录。

## ADR-03：为什么 V1 不用 git2 crate 而用系统 git

**决策**：V1 使用 `std::process::Command` 调用系统 git，V2 迁移至 `git2` crate

**原因**：
- `git2` crate（libgit2）编译时间长，增加构建复杂度
- V1 的目标是快速交付（两周），git 功能需求简单（只需要 `add -A` + `commit`）
- 用户如果没装 git，V1 设计为静默降级（不报错，版本历史不可用）
- V2 有内嵌 libgit2 的必要（消除外部依赖），但 V1 暂不需要

**可以做的**：V1 按此方案实现，V2 阶段可以迁移

## ADR-04：为什么 V1 不做文件变动自动同步（Watcher）

**决策**：V1 用户手动点击「立即同步」按钮，无自动监听

**原因**：
- `tauri-plugin-fs` 的 Watcher 在 Windows 下有已知的路径监听 bug（特定中文路径）
- V1 优先保证核心功能稳定（同步正确性），不追加复杂功能
- 用户手动同步是更可控的体验，不会有意外的后台写入

**不可推翻**：V1 不做 Watcher，这是有意设计，不是遗漏。V2 再加。

## ADR-05：为什么 Cursor 被移出 V1

**决策**：Cursor 移入 V2，V1 不支持

**原因**：
- 开发环境中 Cursor 未安装，无法进行 Spike 验证
- CrossBrain 的设计原则：必须 Spike 验证后才能实现 Adapter，严禁盲目实现
- Cursor 的 `.cursor/rules/*.mdc` 机制与其他工具的 `.md` 机制有差异，需要单独处理

**不可推翻**：不要在 V1 中添加 Cursor Adapter，即使实现看起来简单。

## ADR-06：为什么禁止字符串拼接路径

**决策**：全程使用 `dirs` crate + Rust `Path`/`PathBuf` API

**原因**：
- Windows 路径分隔符为 `\`，Unix 为 `/`，字符串拼接极易出错
- `%USERPROFILE%` 在 Windows 下可能是 `C:\Users\xxx` 或 `D:\Users\xxx`（取决于系统安装位置）
- 某些企业环境会自定义 home 目录到 `E:\Profiles\xxx`，硬编码 `C:\Users` 直接崩溃

**不可推翻**：任何字符串拼接的路径代码都是 bug，必须重写。

## ADR-07：为什么禁止 shell `date` 命令

**决策**：使用 `chrono` crate 生成时间戳

**原因**：
- Windows 没有 `/bin/sh`，调用 `sh -c "date ..."` 会直接 panic
- PowerShell 的 `Get-Date` 格式与 Unix `date` 完全不同
- `chrono` 是纯 Rust 实现，跨平台一致，零系统依赖

**不可推翻**：任何调用系统 `date` 命令的代码都会在 Windows 上崩溃。

## ADR-08：为什么 UI 界面禁止展示内部术语

**决策**：L0/L2/Adapter/SSOT/slug/frontmatter 等术语严禁出现在任何用户可见的界面

**原因**：
- CrossBrain 的目标用户不是开发者，是普通 AI 工具使用者
- 暴露「你现在的全局规则（L0）将被同步到 Antigravity IDE 的 rules/ 目录（L2 路径）」会让用户完全困惑
- 用户看到的永远只是「全局规则」和「技能知识」

**不可推翻**：如果你在 UI 中输出了技术术语，需要改成用户友好语言。

## ADR-09：为什么孤儿清理只删除 `crossbrain-` 前缀的目录

**决策**：`cleanup_orphans()` 只处理 `crossbrain-` 前缀的目录，其他目录一律跳过

**原因**：
- 用户可能在 `~/.gemini/config/skills/` 或 `~/.claude/skills/` 下有自己创建的技能目录
- CrossBrain 对这些目录没有任何管辖权
- 误删用户自建目录属于严重的数据破坏

**不可推翻**：扫描逻辑必须包含 `if !name.starts_with("crossbrain-") { continue; }` 这样的过滤。

## ADR-10：为什么使用 Apache-2.0 而不是 MIT

**决策**：License 选用 Apache-2.0

**原因**：
- Apache-2.0 包含**专利授权条款**，保护贡献者和用户免受专利诉讼
- MIT 无专利条款，在 AI 工具领域有潜在专利风险
- Apache-2.0 对企业和开源生态均友好

**不可推翻**：不要建议改为 MIT 或 GPL。

## ADR-11：为什么 V1 不做文件名拼音转换（TASK-07）

**决策**：slug 的 kebab 段只保留 ASCII 字母数字（转小写），**非 ASCII 字符一律折叠为 `-`**，
不引入拼音词典把「组件性能优化」转写成 `zujian-xingneng-youhua`。

**原因**：
- 拼音转写需要词典 + 多音字消歧（「重庆」「银行」），词典体积与维护成本都不划算
- `ARCHITECTURE.md` 第 4 节示例里的 `vue3-perf` 是**人工示意**，不是算法产物——
  该示例的 `perf` 是人工概括，任何词典都无法由「组件性能优化」推出 `perf`
- 可行性不受影响：区分度由 hash 段承担（内容不同则 hash 不同，不会互相覆盖）

**已接受的代价**：**纯中文文件名**的 kebab 段退化为兜底值 `item`，
目录名形如 `crossbrain-item-7a6883`，人工排障时看不出对应哪个知识点。
补偿措施：**UI 侧必须始终展示「文件名 → 目录名」映射**，不让用户直接面对目录名。

**✅ 决策确认（2026-09-14，用户拍板）**：采纳上述补偿方案 ——
**UI 侧始终展示「源文件名 → 注入后目录名」映射**；
不引入拼音词典，也**不改 slug 规格**（V1.1 的「兜底时混入文件名 hash」方案暂不采纳）。

落实位置与就绪状态：

| 位置 | 状态 |
|:---|:---|
| `PRD.md` 第 6.2 节：技能卡片必须同时展示文件名与目录名 | ✅ 已写入 |
| TASK-12 验收清单（技能知识卡片列表） | ⏳ 待 TASK-12 实现 |
| Rust 侧数据源 | ✅ 已就绪：`sync::KnowledgeItem` 同时携带 `file_name` 与 `dir_name`，由 `scan_knowledge()` 直接产出，UI **不需要**自行反推 |

**可以做的**：V1.1 若产品需要，可在兜底场景混入文件名 hash
（`crossbrain-item-3f2a1b-7a6883`）提升可区分度——但**这是规格变更**，
需要同步改 `ARCHITECTURE.md` 第 4 节、`TEST_PLAN.md` T1 与本文件的 ADR-02。

**不可推翻**：不要为「更漂亮的名字」引入拼音词典或联网转写服务——
后者还会破坏「零网络依赖」的产品定位（见 ADR-04 的离线定位）。

## ADR-12：IPC 层独立为 `commands.rs`，只做转发（TASK-10）

**决策**：前端与 Rust 之间只经由 `src-tauri/src/commands.rs` 的
`#[tauri::command]` 函数通信；该文件**只做参数转发与错误文案转换**，
不含任何业务逻辑。

**原因**：

- Tauri 的 IPC 是**字符串寻址**的：命令名写错在编译期完全不可见，
  只有用户点下去那一刻才失败（表现为「按钮没反应」这种最难排查的形态）
- 若把编排逻辑写在 command 里，TASK-10 的向导与 TASK-13 的「立即同步」
  会各实现一遍，必然分叉
- 业务逻辑放 `sync.rs` 后可以**脱离 Tauri 运行时被测试**：
  `run_for_tools()` 不依赖 `AppHandle`，事件只是它的一个消费者

**配套约束（三者缺一都会静默失败）**：

1. 命令名 / 事件名 / DTO 字段名的两侧一致性由 `tests/ipc_contract.rs` 锁定。
   它比对的是**两侧的真实源码文本**，而不是手写清单——手写清单本身就是
   「两处各写一份」，正是要防的东西。
2. 同步进度经 `sync://progress` 事件推送，而不是等全部完成一次性返回
   （向导的硬性验收项：逐行实时显示）。
3. `run_sync` 必须是 `async` + `tauri::async_runtime::spawn_blocking`：
   同步的文件 IO 若占住主线程，前端**收得到事件也渲染不出来**，
   「实时显示」会退化成假实时。

**不引入前端路由库**：V1 只有「向导」与「主工作台」两个顶层视图，
主工作台内部是 3 个 Tab，用 `App.vue` 的一个布尔状态切换即可，零依赖。
V2 若页面显著增多（多机同步、版本历史时间轴等）应重新评估此决策。

## ADR-13：应用状态持久化到 `.crossbrain-state.json`（TASK-10）

**决策**：新增 `~/.ai-profile/.crossbrain-state.json` 保存本机状态
（`wizard_completed` / `last_sync_at` / `last_sync_ok`），
并把文件名写入 SSOT 的 `.gitignore`。

**原因**：

- `PRD.md` 把向导触发条件定义为「`rules.md` 存在但内容为空」，
  但用户完全可以一字不写就点「跳过，直接进入」——此时该条件**永远成立**，
  下次启动会反复弹出向导，与验收项「向导完成后再次启动不再显示」直接冲突
- `PRD.md` 第 7 节的状态栏要显示「上次同步时间」，重启后必须还在

**明确边界**：

- 它是**本机状态**，不是用户内容：不参与同步、不进版本历史
  （多机同步时状态文件会互相冲突）
- 状态文件丢失或损坏**不得阻断启动**：最坏情况只是重新显示一次向导。
  因此读取失败一律回退默认值，**不返回 `Err`**——把「状态文件读不出来」
  升级成「应用打不开」是错误的优先级
- `.gitignore` 采用**幂等逐行补齐**而不是覆盖写入：那是用户的文件，
  直接覆盖会删掉用户自己加的忽略规则；条目齐全时**完全不写盘**
  （保证 TASK-03 的「二次启动 mtime 零变化」断言仍成立）

**不可推翻**：不要把状态塞进 `rules.md`、或借助文件名/目录是否存在来表达状态。

## ADR-14：SSOT 读取失败时中止同步，绝不退化为「空」（TASK-10）

**决策**：同步开始前读取 `global/rules.md` 并扫描 `knowledge/`，
**任何读取失败都整体中止**——一个 Adapter 都不调用，
向用户报告「同步失败」而不是继续执行。

**原因**：`cleanup_orphans()` 的语义是「删除不在本次有效 slug 列表里的
`crossbrain-*` 目录」，因此**空列表等于删光用户全部技能目录**。
若 `knowledge/` 因文件被占用、权限异常或盘符离线而读不出来，
而代码把「读不出来」当成「目录里没有文件」，就会在数据不完整的状态下执行删除——
**用户的源文件还在，注入到各工具的技能却全没了**。

**判定规则**：

| 情况 | 处理 |
|:---|:---|
| `knowledge/` 存在且真的没有 `.md` 文件 | 正常同步，`active_slugs` 为空（清理是正确行为） |
| `knowledge/` 或其下任一文件**读取失败** | **整体中止** |
| `rules.md` **不存在** | 视作「用户还没写」，返回空串（不是错误） |
| `rules.md` 存在但**读取失败** | **整体中止** |

**已接受的代价**：同步更「脆」——一次瞬时的文件占用就会让整次同步失败。
这是刻意的取舍：**失败是可见且可重试的，误删是不可逆的**。

**不可推翻**：不要为了「更健壮」而把读取失败降级为「跳过这一项」。

## ADR-15：对用户文件的改动必须「知情且可逆」（TASK-19）

**决策**：CrossBrain 对用户既有文件的两类改动，各补一条强制要求：

| 要求 | 内容 |
|:---|:---|
| **可逆** | 备份不能「只写不读」。必须提供界面入口，让用户能把 `*.crossbrain-backup` 还原回原文件。 |
| **知情** | 凡**改变用户既有结构**（而非仅追加内容）的操作，必须在**执行前**明确告知。 |

**触发**：2026-09-14 深夜的安全边界核查（用户提问「会不会破坏用户原有编程软件的用户偏好配置」）。

**原因**：

1. **「不会破坏用户配置」当时少了一环。** `MARKER_BACKUP_SUFFIX` 只在
   `inject_marker_block()` 的情况三生成备份（`fs::copy`），而**全仓库没有任何读取它的代码**；
   `commands.rs` 的 6 条命令里没有 restore/rollback。结论是：内容确实备份了，
   但用户**在界面上点不到「还原」**，只能自己进文件系统改名。
   对一个桌面应用来说，「备份了但恢复不了」在承诺上等于不可逆。
2. **D-03 的断链是有意改变用户既有结构。** `~/.claude/CLAUDE.md` 首次同步后脱离
   5 路共享 inode（links 5 → 1）。内容一字不变，但此后不再跟随其余 4 处一起变更。
   而用户**本来就是靠硬链接实现「一份内容、5 个工具生效」**的（文件首行自称
   Global AI Memory Hub）——断开一侧属于改变用户既有的工作流，必须事前告知，不能只在
   代码注释和文档里写着。

**边界（明确不做的）**：

- 不提供「回滚整次同步」——那需要事务日志，超出 V1 范围。
- 不自动还原——还原必须是用户的显式动作，不由程序推断。
- `.crossbrain-backup` 是**唯一的干净快照**（首次注入前的原始内容），
  **任何代码路径都不得覆盖它**，滚动覆盖、还原流程都不例外。

**已接受的代价**：用户若先手改了目标文件、再执行还原，会丢掉那次手改。
缓解方式是还原前先把当前版本另存为 `*.crossbrain-before-restore`（见 TASK-19），
确保**两个方向都能退回去**。

**不可推翻**：不要为了「简化」只做还原而不做告知；也不要把还原做成静默的自动行为。
