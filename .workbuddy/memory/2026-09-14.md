### 三个坑（都踩过并解决，细节写在 docs/impl/DEV_SETUP.md）

**坑 1：VS 安装器 5008/5002 → 环境变量大小写重复**
日志里是 `Error 0x80070057: 已添加项。字典中的关键字:"http_proxy"所添加的关键字:"HTTP_PROXY"`。
VS 安装器用忽略大小写的 .NET 字典装载环境变量，遇到重复键直接崩在启动 setup.exe 之前。
本机有 3 组重复：`http_proxy`/`HTTP_PROXY`、`https_proxy`/`HTTPS_PROXY`、`Path`/`PATH`
（**Path 与 PATH 值不同**，Path=853 字符，PATH=962 字符且是前者的超集 → 保留 PATH）。
解法：启动子进程前在同一进程内循环去重（PowerShell 的 `Env:` 驱动器忽略大小写，
所以 `Remove-Item Env:\x` 删哪个不确定，必须循环删到只剩一个，再显式写回想要的值）。
⚠️ **去重和启动必须在同一条命令里**，因为 PowerShell 工具每次调用都是新进程。

**坑 2：VS 安装器自身缺陷（Unexpected Installer Version）**
需先下载 `https://aka.ms/vs/install/latest/installer`（~48MB 的 vs_installer.opc），
用 `vs_BuildTools.exe --quiet --wait --update --offline <opc>` 把 installer 本体更新到位，
再跑真正的安装。**别加 `--nocache`**（会清掉刚下的 opc）。

**坑 3：rustup 走代理卡死（60 秒零增量）+ rust-docs 解压极慢（0.1 MB/s）**
① 用清华镜像 + **直连**（移除全部代理变量）：`RUSTUP_DIST_SERVER=https://mirrors.tuna.tsinghua.edu.cn/rustup`；
② `--profile minimal` 参数在「恢复半成品」路径下**不生效**，必须用持久的 `rustup set profile minimal`，
然后 `rustup toolchain uninstall stable` 清半成品再装 —— 否则它会按上次的 default profile 把 rust-docs 又装一遍。

**附注**：`where link.exe` 命中 PortableGit 的 coreutils 同名工具，属无害冲突——
rustc 走 vswhere/注册表定位 MSVC linker，不依赖 PATH。

**方法论**：判断「Rust 装好没有」的标准是**能编译并链接**，不是 `rustc --version` 能打印。
`--version` 在 linker 缺失时照样成功，真正的坑要等 `cargo build` 才暴露。

### 关键坑：`拒绝访问 (os error 5)` 是本机的系统性现象 ⚠️

**首次 `cargo build` 失败**，退出码 101：

```
error: failed to run custom build command for `proc-macro2 v1.0.107`
  Failed to clean up ...\target\debug\build\proc-macro2-xxxx\out\probe: 拒绝访问。 (os error 5)
```

**排查过程（别走弯路）**：
- 先怀疑杀软 → 实测 `RealTimeProtectionEnabled = False`（Defender 实时保护本来就没开），
  也无任何第三方杀软进程 → **不是杀软，不需要配排除项**
- 查磁盘（NTFS 正常）、查残留 rustc/cargo 进程（无）、查并发（无）→ 都不是
- **真相**：`proc-macro2` 构建脚本会编译探测 exe、执行它、再删临时目录；
  Windows 上刚执行过的 exe 句柄释放有延迟，`remove_dir_all` 撞上 `ERROR_ACCESS_DENIED` 就 exit 1

**解法**：`rm -rf target/debug/build/proc-macro2-*` 后重试，一次即过。
同类错误还会以 **warning** 出现（`error copying object file ... to incremental directory ...: 拒绝访问`），
只影响增量元数据、编译仍成功。

**结论**：本项目在这台机器上，**遇到 Rust 构建失败先怀疑 os error 5，不要先怀疑代码**。
清理 `target/debug/build/<crate>-*` 重试是标准动作。（已固化进 skill `windows-rust-tauri-setup`）

### 🔴 Windows 断链写入三步法（本项目硬约束，也是通用技巧）

```rust
let tmp = path.with_file_name(format!("{}.crossbrain-tmp", name));
fs::write(&tmp, content)?;          // ① 内容先落盘（失败也不丢数据）
match fs::remove_file(path) {       // ② 断链的关键一步
    Ok(()) => {}
    Err(e) if e.kind() == ErrorKind::NotFound => {}   // 文件本不存在（情况一）
    Err(e) => { let _ = fs::remove_file(&tmp); return Err(/* 明确报错 */); }

```

// 后置：断链后向 a 就地覆写，b 必须纹丝不动

### 🔴 最关键的坑：按字节下标切 UTF-8 字符串会 panic

原文档 `filename_to_slug` 用 `slug[..30]` 截断、用 `trim_end_matches(".md")` 去扩展名。
**只要实现里出现 `filename[name.len() - 3..]` 这类字节下标，就会踩中文崩溃**：

```rust
"优化".len() == 6           // UTF-8 每汉字 3 字节
"优化".len() - 3 == 3      // 落在第二个汉字的中间
&"优化"[..3]                // 💥 panic: byte index 3 is not a char boundary
```

**正确写法**（本项目以后所有字符串处理都按这个来）：

```rust
let idx = filename.len().checked_sub(3)?;
if filename.is_char_boundary(idx) && filename[idx..].eq_ignore_ascii_case(".md") {
    &filename[..idx]
} else { filename }
```

**通用规则：Rust 里任何 `str` 下标运算（`s[i..]` / `s[..i]` / `s[i..j]`）在 Unicode 输入下
都是潜在的 panic 点。** 要么用 `chars()` 迭代器，要么先过 `is_char_boundary`。
本项目文件名**必然含中文**（用户的 knowledge/ 全是中文名），所以这是必踩的坑而不是理论风险。

### hash 段必须用 SHA-256，不能用 `DefaultHasher`

`std::collections::hash_map::DefaultHasher` 的输出**不保证跨 Rust 版本稳定**。
用它做内容寻址 → 升级工具链后**所有 slug 全变 → 全量技能目录被判为孤儿而删除重建**。
内容寻址的标识符必须是可跨版本、跨机器复现的 —— 这正是不用 `DefaultHasher` 的原因。

**验收方法（比单元测试更硬）**：拿系统 `sha256sum` 的输出做外部交叉验证。
`printf 'test' | sha256sum` → `9f86d081...` → 前 6 位 `9f86d0`，
断言程序输出 `crossbrain-vue3-9f86d0`。这证明算的是**标准 SHA-256**，而不是某个自洽的私有实现。
标准向量（`"abc"` / `""`）也可写进测试做固定断言。

### 🔴 同步流程的安全铁律：读不出来 ≠ 空的（ADR-14）

`cleanup_orphans()` 的语义是「删除不在本次有效 slug 列表里的 `crossbrain-*` 目录」，
所以**空列表 = 删光用户全部技能目录**。

如果 `knowledge/` 因占用/权限/盘符离线读不出来，而代码把它当成「目录里没有文件」，
就会在**数据不完整**的状态下执行删除 → 用户源文件还在，注入的技能全没了。

**判定规则**：目录存在且确实没有 `.md` → 正常同步（空列表是正确输入）；
目录或其下任一文件**读取失败** → **整体中止，一个 Adapter 都不调用**。

代价是同步更「脆」（一次瞬时占用就整体失败），但**失败可见可重试，误删不可逆**。

### 「逐行实时显示」要求主线程不被阻塞

同步是阻塞式文件 IO。若 `run_sync` 写成普通同步命令，主线程被占 → 
**前端收得到事件也渲染不出来**，验收项「实时显示」退化成假实时。

必须 `async fn` + `tauri::async_runtime::spawn_blocking`，
进度经 `emit("sync://progress", ...)` 逐个工具推送。

**通用规则：只要 UI 要求「过程可见」，后端就不能阻塞主线程——
事件发出去了不等于画面能更新。**
